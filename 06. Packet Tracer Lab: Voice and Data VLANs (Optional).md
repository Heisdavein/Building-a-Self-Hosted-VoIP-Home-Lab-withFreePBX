# 06. Packet Tracer Lab: Voice and Data VLANs (Optional)

Back to README | Previous: Softphone and validation | Next: Troubleshooting

A production VoIP deployment involves more than a PBX. Concepts such as VLANs, DHCP, DHCP Option 150, trunk links, access ports and Quality of Service matter as much as the PBX. I do not own enterprise Cisco switches, routers or IP phones, so I used Cisco Packet Tracer to simulate the network side.

> **Scope note**
> 
> 
> This part is a standalone simulation. The Packet Tracer network is not connected to the FreePBX VM from Part A. Its purpose was to practise how voice and data are separated on an enterprise network.
> 

## 1. Install Packet Tracer

Packet Tracer is Cisco’s network simulator for students and professionals. It simulates networks of routers, switches, servers, PCs, wireless devices and IP phones, and models many protocols and device behaviours.

1. Visit the Cisco Networking Academy website and search for Cisco Packet Tracer.
2. Create a free Networking Academy account and enrol in the introductory Packet Tracer course, which unlocks the download.
3. Download the Windows version and run the installer with default options.
4. Launch Packet Tracer and sign in with the same Networking Academy account. It opens with an empty workspace and the device palette along the bottom.

## 2. Build the topology

I kept the design to four devices so I could concentrate on the VoIP networking concepts:

| Device | Role |
| --- | --- |
| Cisco router | Layer 3 routing and DHCP |
| Cisco switch | Connects end devices and separates traffic with VLANs |
| Desktop PC | Normal data device |
| Cisco IP phone | Voice endpoint |

Cabling:

| From | To |
| --- | --- |
| Router | Switch |
| PC | Switch FastEthernet0/1 |
| IP phone | Switch FastEthernet0/2 |

```
        Router
          |
          |
     Cisco Switch
       /      \
      /        \
    PC       IP Phone
```

The layout mirrors a basic small business VoIP deployment.

## 3. Create the voice VLAN

On the switch CLI:

```
enable
configure terminal
vlan 2
 name Voice
 exit
```

`vlan 2` creates the VLAN and `name Voice` labels it. VLAN 1 already exists by default and carries data traffic. The switch now has two logical networks, VLAN 1 for data and VLAN 2 for voice, on the same physical switch.


## 4. Configure the access ports

PC port, data VLAN:

```
interface FastEthernet0/1
 switchport mode access
 switchport access vlan 1
 exit
```

IP phone port, data VLAN plus voice VLAN:

```
interface FastEthernet0/2
 switchport mode access
 switchport access vlan 1
 switchport voice vlan 2
 exit
```

The voice VLAN configuration lets the switch tell voice traffic from ordinary data on the same port. In many deployments the phone sits between the switch and the user’s PC. The phone tags its own voice packets with the voice VLAN and passes the PC’s traffic on the data VLAN. My topology did not have a PC behind the phone, but the configuration reflects how Cisco switches are set up in production.

## 5. Configure router-on-a-stick

With two VLANs on the switch, the router needs to reach both. Instead of using two physical interfaces I used one interface with a subinterface per VLAN, a design known as router-on-a-stick.

```
interface FastEthernet0/0.1
 encapsulation dot1Q 1
 ip address 192.168.1.1 255.255.255.0

interface FastEthernet0/0.2
 encapsulation dot1Q 2
 ip address 192.168.2.1 255.255.255.0
```

`encapsulation dot1Q` tells the router which VLAN each subinterface serves. The subinterface addresses become the default gateways:

| VLAN | Subnet | Gateway |
| --- | --- | --- |
| 1 (data) | 192.168.1.0/24 | 192.168.1.1 |
| 2 (voice) | 192.168.2.0/24 | 192.168.2.1 |

This allows inter-VLAN routing when devices in different VLANs need to communicate.

## 6. Separate DHCP services

I created a DHCP pool on the router for each VLAN so devices receive an address from their own subnet:

| VLAN | Network |
| --- | --- |
| Data (VLAN 1) | 192.168.1.0/24 |
| Voice (VLAN 2) | 192.168.2.0/24 |

Separate scopes keep voice and data logically apart and simplify administration. The pool commands themselves are not reproduced in this guide, because they were not captured in my written notes; see the placeholder below.

## 7. Verify VLAN separation

I set the PC to obtain its address by DHCP, then checked the IP phone.

| Device | Result |
| --- | --- |
| PC | Received an address in `192.168.1.x` |
| IP phone | Received an address in `192.168.2.x` |

Both devices are on the same physical switch but landed on different logical networks purely from the switch port configuration. That showed the switch, router, VLAN configuration and DHCP were all working.

## Reflection

This was where the networking theory became practical. Voice VLANs, access ports and router-on-a-stick had been textbook terms until I watched the PC and the phone receive addresses from completely different subnets while plugged into the same switch. Segmentation comes from configuration, not from separate cabling. In real deployments this separation supports both security and call quality.
