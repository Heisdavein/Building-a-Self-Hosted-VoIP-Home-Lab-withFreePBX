# 03. FreePBX Installation

Back to README | Previous: VirtualBox and VM | Next: FreePBX web setup

This guide covers booting the installer, setting the root password, installing the system, and confirming the server’s IP address on first boot.

## 1. Start the VM and boot the installer

Select the FreePBX VM and click **Start**. Because the ISO is attached to the virtual optical drive, the VM boots from it instead of the empty virtual disk, the same as inserting a DVD into a physical server.

At the FreePBX boot menu I left the default installation option selected and pressed `Enter`. The installer then loaded the Linux kernel and environment. The system messages that scroll past during this stage are normal. In the background the kernel loads, hardware (CPU, RAM, storage controller, network adapter) is detected, drivers load and the graphical installer starts.

## 3. Set the root password

The one required configuration task was the root password.

1. Select **Root Password**.
2. Enter a strong password and confirm it.
3. Click **Done**. If the installer judges the password too weak it can warn before continuing.

Root is the Linux superuser: it can install or remove software, edit system files, manage users and services, change firewall rules, read every file and reboot the machine. Anyone who obtains it controls the server. I treated the password seriously even in a home lab: long, mixed case, numbers and special characters, no dictionary words or personal information.

## 4. Install

Select **Begin Installation**. The installer then works on its own: partitioning the virtual disk, creating and formatting the filesystem, installing Linux, Asterisk and FreePBX and required packages, configuring core services and setting up the bootloader. I let it run without interruption.

The bootloader is a small program that runs right after power-on. It locates the operating system, loads the Linux kernel into memory and hands control to Linux. Without it the server could not start the system on the disk.

## 5. Complete the installation

After several minutes the installer reported success. I clicked **Reboot**. VirtualBox stopped booting from the ISO and the VM started from the virtual disk, so it was now running the installed system rather than the installer. The first boot took slightly longer while Linux finished post-install tasks and started services for the first time.

## 6. First boot and the console

FreePBX has no desktop environment. It is a server: local interaction is through a text console and day-to-day administration is done in the web interface. After boot, the console showed a login prompt and a system summary with the hostname, status and network information. The startup finished with no installation errors or boot failures.

## 7. Identify the IP address

The console displays the server’s current IP address after boot. Because the adapter is bridged, the router’s DHCP server gave the VM its own address on the same network as the Windows laptop. In the documented run the console showed an address similar to:

```
192.168.1.149
```

Your address will differ. I noted it straight away because everything later uses it: the browser, the softphone and any future SIP device.

## 8. Verify the address from the command line

I logged in as `root` and ran:

```bash
ip addr show | grep "inet "
```

| Part | Meaning |
| --- | --- |
| `ip` | Modern Linux utility for interfaces, addresses and routes, replacing older tools such as `ifconfig` |
| `addr` | Show address information |
| `show` | Display the current configuration without changing it |
| `grep "inet "` | Keep only IPv4 lines |

Example output from the lab:

```
inet 127.0.0.1/8 scope host lo
inet 192.168.1.149/24 brd 192.168.1.255 scope global dynamic ens160
```

`127.0.0.1` is the loopback address used internally. `192.168.1.149` is the server’s real address, matching the console. The interface name is shown as it appeared in my recorded output.

Confirming with a command rather than trusting the banner is a troubleshooting habit. A missing or unexpected address would point to the wrong VirtualBox adapter, bridged mode set up incorrectly, the router’s DHCP server not responding, or the interface failing to start.
