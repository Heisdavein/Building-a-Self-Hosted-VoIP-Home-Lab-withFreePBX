# 02. VirtualBox and Virtual Machine

Back to README | Previous: Host readiness | Next: FreePBX installation

This guide covers installing VirtualBox, downloading the FreePBX ISO, creating the VM, attaching the ISO and setting the network mode.

## 1. Install VirtualBox

A hypervisor lets one physical computer run several operating systems independently. I chose Oracle VirtualBox because it is free, widely used, supports the Linux base that FreePBX uses, and lets me change CPU, memory, storage and networking without touching the physical machine.

1. Open the official Oracle VirtualBox website and go to **Downloads**.
2. Under **VirtualBox for Windows hosts**, download the Windows installer.
3. Run the installer and accept the default directory and components.
4. Windows warns that the network connection will be briefly interrupted while VirtualBox installs its virtual network adapters. Allow it to continue, since the VM needs those adapters.
5. Leave **Start Oracle VirtualBox after installation** enabled and click **Finish**.

The VirtualBox Manager opened with an empty VM list, confirming a clean install.

## 2. Download the FreePBX ISO

I downloaded the installer only from the official FreePBX website so the image was authentic and unmodified. The **Sangoma FreePBX Distribution ISO** bundles:

- the Linux operating system
- the Asterisk PBX software
- the FreePBX web management interface
- supporting services and dependencies

Steps:

1. Go to the official FreePBX website and open **Downloads**.
2. Choose the latest stable FreePBX Distribution ISO for a fresh installation.
3. Complete the registration form (email address, country, deployment type). The download starts automatically.
4. Wait for the multi-gigabyte download to finish.
5. Confirm the ISO is saved in the Downloads folder and note the path, because it is attached to the VM in a later step.

## 3. Create the virtual machine

1. Open VirtualBox Manager and click **New**.
2. Name: `FreePBX`.
3. Type: **Linux**.
4. Version: **Red Hat (64-bit)**, because the FreePBX Distribution is built on a Red Hat Enterprise Linux based platform.
5. Hardware: **2048 MB** RAM and **2** CPUs.
6. Select **Create a Virtual Hard Disk Now**.
7. File type: **VDI (VirtualBox Disk Image)**.
8. Storage: **Dynamically allocated**.
9. Size: **40 GB**.
10. Click **Finish**.

The VM appeared in the Manager in a powered-off state.

| Setting | Value |
| --- | --- |
| Name | FreePBX |
| Type / Version | Linux / Red Hat (64-bit) |
| RAM | 2048 MB |
| CPUs | 2 |
| Disk | 40 GB VDI, dynamically allocated |

I kept the VM modest on purpose. FreePBX runs well on small resources in a lab with a few test calls, and the host stays responsive. The dynamic disk starts small on the SSD and grows as needed.

## 4. Attach the ISO

A new VM has virtual hardware but no operating system. The ISO acts like a bootable DVD in a physical machine. Without it the VM reports errors such as `No bootable medium found` or `FATAL: No bootable device.`

1. Select the FreePBX VM and click **Settings**.
2. Open the **Storage** category.
3. Under **Controller: IDE** (or **SATA**, depending on the VirtualBox version), select the empty optical drive.
4. Click the disc icon beside the drive, choose **Choose a Disk File**, and browse to the FreePBX ISO.
5. Confirm the ISO is listed as the virtual DVD.

## 5. Configure the network adapter

1. In **Settings**, open **Network**.
2. Under **Adapter 1**, make sure **Enable Network Adapter** is ticked.
3. Set **Attached to** to **Bridged Adapter**.
4. Under **Name**, select the physical adapter the laptop is using (Wi-Fi or Ethernet).
5. Click **OK**.

NAT, VirtualBox’s default, hides the VM behind the host’s address and makes it harder for other devices to start connections to it. Bridged mode connects the VM straight to the home router, so it receives its own address and acts like any other computer on the LAN, with its own MAC address, IP address and traffic.

```
                 Home router
                      |
      +---------------+---------------+
      |               |               |
 Windows laptop    FreePBX VM     Smartphone
 192.168.1.100    192.168.1.150   192.168.1.120
```

The addresses above are illustrative. The VM’s real address is read from the console after first boot (next guide).

This matters later because I need to open the web interface from the browser, register softphones against the server’s IP, let SIP traffic reach the server and test calls between devices.
